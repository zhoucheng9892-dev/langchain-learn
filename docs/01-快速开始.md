# 第 1 章 快速开始：十分钟跑起来

> 本章代码：`chapters/ch01_quickstart/01_hello_model.py`、`02_first_agent.py`

## 1.1 本章目标

- 在本地跑通第一个模型调用和第一个 Agent
- 理解 v1 最重要的观念转变：**框架的核心不再是 Chain，而是 Agent**
- 知道 `invoke` 返回的是什么、为什么不是字符串

## 1.2 LangChain 1.x 到底变了什么

LangChain 1.0 于 2025 年 10 月 22 日发布，与 LangGraph 1.0 同日。它做了一次"减法"：

| 变化 | 说明 |
| --- | --- |
| 新的统一入口 | `create_agent` 取代 `AgentExecutor` 和 `langgraph.prebuilt.create_react_agent` |
| 中间件成为扩展点 | 想改行为不再靠堆构造参数，而是挂中间件（钩子） |
| 命名空间精简 | `langchain` 只留核心构件，旧功能搬到独立包 `langchain-classic` |
| 标准内容块 | 新增 `content_blocks`，把文本、图片、推理过程统一成同一套结构 |

一句话记住：**v1 = 一个 Agent 循环 + 一套中间件机制**。你在网上看到的大部分教程都是 0.x 的写法，`from langchain.chains import LLMChain` 这类代码在 v1 里会直接 ImportError，因为那个模块根本不在 `langchain` 包里了。

## 1.3 本项目怎么用

```bash
# 1. 装依赖（已配好 uv，会读取 pyproject.toml）
uv sync

# 2. 配密钥
cp .env.example .env        # 然后填入 DEEPSEEK_API_KEY

# 3. 跑第一个示例
uv run python chapters/ch01_quickstart/01_hello_model.py
```

`.env` 里只有两个关键项：

```ini
DEEPSEEK_API_KEY=sk-xxx
MODEL_NAME=deepseek-v4.1-flash
```

> **坑：产品名 ≠ API 模型名**
> DeepSeek 的 OpenAI 兼容接口只接受 `deepseek-flash` 和 `deepseek-v4-pro`。
> 传 `deepseek-v4.1-flash` 会报 400：`The supported API model names are deepseek-flash, deepseek-v4-pro`。
> 本项目在 `src/langchain_learn/llm.py` 里做了别名映射，所以你写产品名也能跑。

## 1.4 最小可运行代码

```python
from langchain_deepseek import ChatDeepSeek

# deepseek-flash 就是 v4.1-flash 的 API 名字
model = ChatDeepSeek(model="deepseek-flash", reasoning_effort="none")
reply = model.invoke("用两句话说明 LangChain 1.x 是什么。")

print(type(reply).__name__)     # AIMessage
print(reply.content)            # 文本在这里
print(reply.usage_metadata)     # token 用量
```

三个必须知道的细节：

1. **返回值是 `AIMessage`，不是 `str`**。文本在 `.content`，元信息在 `.usage_metadata` 和 `.response_metadata`。
2. **`reasoning_effort="none"` 关掉了思考模式**。v4 默认先"思考"再回答，思考内容在 `additional_kwargs["reasoning_content"]`，不关掉会让示例变慢、变贵，还会让结构化输出报错（第 4 章细讲）。
3. **模型本身无状态**。它不记得你上一句说了什么，记忆全靠传进去的消息列表。

## 1.5 第一个 Agent

```python
from langchain.agents import create_agent
from langchain.tools import tool


@tool
def get_weather(city: str) -> str:
    """查询指定城市的当前天气。"""
    return {"北京": "晴，25°C"}.get(city, "暂无数据")


agent = create_agent(
    model="deepseek:deepseek-flash",
    tools=[get_weather],
    system_prompt="需要外部数据时必须调用工具，不要编造。",
)

result = agent.invoke({"messages": [{"role": "user", "content": "北京天气怎么样？"}]})
print(result["messages"][-1].content)
```

跑完之后 `result["messages"]` 里会是 4 条消息，这就是 Agent 的全部秘密：

```
HumanMessage  ->  AIMessage(带 tool_calls)  ->  ToolMessage  ->  AIMessage
    用户提问         模型决定调工具              工具返回结果        模型总结
```

`create_agent` 做的事情，就是把这条链循环起来，直到模型不再请求工具。

## 1.6 同一件事的三种写法，什么时候用哪个

| 写法 | 适用场景 | 代码位置 |
| --- | --- | --- |
| 直接调模型 `model.invoke()` | 单轮生成、分类、抽取、改写 | `01_hello_model.py` |
| 管道 `prompt \| model \| parser` | 流程固定、无工具、要高吞吐 | 第 3 章 |
| `create_agent()` | 需要调工具、多步推理、要记忆 | `02_first_agent.py` |

**不要一上来就上 Agent**。能用一次模型调用解决的问题，用 Agent 只会更慢更贵更不稳定。

## 1.7 常见坑

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| `ImportError: cannot import name 'LLMChain'` | 抄了 0.x 教程 | 改用 `prompt \| model`，或安装 `langchain-classic` |
| 400 模型名不支持 | 用了产品名 | 用 `deepseek-flash` 或项目里的 `get_model()` |
| 返回内容为空字符串 | 思考模式吃光了 `max_tokens` | `reasoning_effort="none"` 或把 `max_tokens` 调到 1024+ |
| 工具没被调用 | docstring 写得太含糊 | docstring 是给模型看的说明书，必须写清"做什么、参数是什么" |
