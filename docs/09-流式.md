# 第 9 章 流式：四种粒度的"边跑边给"

> 本章代码：`chapters/ch09_streaming/01_stream_modes.py`、`02_sse_and_events.py`

## 9.1 本章目标

- 分清 `updates / values / messages / custom` 四种 stream_mode
- 能给前端产出一个可用的 SSE 流
- 知道 `stream_events` 是干什么的（以及它是实验特性）

## 9.2 四种粒度

| stream_mode | 每次吐出什么 | 典型用途 |
| --- | --- | --- |
| `updates` | 每个节点跑完的增量 state | 步骤条、"正在调用工具" |
| `values` | 每一步的完整 state | 前端整体重渲染 |
| `messages` | 模型输出的 token 增量 + 工具消息 | 打字机效果 |
| `custom` | 工具自己 `writer()` 的内容 | 进度条、抓取进度 |

```python
# 单模式
for chunk in agent.stream(inputs, stream_mode="updates"):
    ...

# 多模式：变成 (mode, payload) 元组
for mode, payload in agent.stream(inputs, stream_mode=["messages", "custom"]):
    if mode == "custom":
        print(payload["step"])
```

实测（`01_stream_modes.py`）：

```
[updates] 节点 model -> ['AIMessage']
          节点 tools -> ['ToolMessage']
          节点 model -> ['AIMessage']

[values]  第 1 步: 1 条消息 (HumanMessage)
          第 2 步: 2 条消息 (AIMessage)
          第 3 步: 3 条消息 (ToolMessage)
          第 4 步: 4 条消息 (AIMessage)

[custom]  进度 33% 抓取 概览 / 67% 最佳实践 / 100% 常见坑
```

## 9.3 messages 模式的正确用法

`messages` 模式吐出的是 `(message_chunk, metadata)` 元组。**必须看 `metadata["langgraph_node"]`**，否则会把工具节点的内容也当成模型输出打出来：

```python
for chunk, meta in agent.stream(inputs, stream_mode="messages"):
    if meta.get("langgraph_node") != "model":
        continue
    if chunk.content:
        print(chunk.content, end="", flush=True)
```

另外：**思考模式的增量在 `additional_kwargs["reasoning_content"]`，不在 `content`**。做"思考中..."的 UI 要判断两个字段。

## 9.4 工具上报进度：custom

```python
@tool
def crawl_pages(topic: str, runtime: ToolRuntime) -> str:
    """抓取页面。"""
    writer = runtime.stream_writer
    for i, page in enumerate(pages, 1):
        writer({"progress": i / len(pages), "step": f"抓取 {page}"})
    return "..."
```

`runtime.stream_writer` 写的内容会从 `stream_mode="custom"` 流出来。做长任务（爬取、批处理、文件转换）时，这是唯一能让用户知道"还在动"的机制。

## 9.5 接到前端：SSE

后端把 chunk 编码成 SSE 帧：

```python
def sse(event: dict) -> str:
    return f"data: {json.dumps(event, ensure_ascii=False)}\n\n"

for mode, payload in agent.stream(inputs, stream_mode=["messages", "updates"]):
    if mode == "messages":
        chunk, meta = payload
        if chunk.content and meta.get("langgraph_node") == "model":
            yield sse({"type": "token", "text": chunk.content})
    else:
        for node, _ in payload.items():
            if node == "tools":
                yield sse({"type": "tool", "status": "done"})
```

前端：

```javascript
const res = await fetch('/chat', {method: 'POST', body: JSON.stringify({q})});
const reader = res.body.getReader();
const decoder = new TextDecoder();
while (true) {
  const {value, done} = await reader.read();
  if (done) break;
  for (const line of decoder.decode(value).split('\n\n')) {
    if (!line.startsWith('data: ')) continue;
    const ev = JSON.parse(line.slice(6));
    if (ev.type === 'token') appendText(ev.text);
    if (ev.type === 'tool') showToolBadge(ev.name);
  }
}
```

FastAPI 里就是 `StreamingResponse(generator(), media_type="text/event-stream")`。

**三个必须注意的点**：

1. `ensure_ascii=False`，否则中文变 `\uXXXX`；
2. 每个帧以 `\n\n` 结尾，否则前端拼不出完整消息；
3. 连接断开要能中止生成，否则白花钱（LangGraph 的 `abort` 事件可以接）。

## 9.6 stream_events：更细的事件协议

```python
stream = agent.stream_events(inputs, version="v3")
for event in stream:
    print(event["method"], event["params"].get("namespace"))
```

输出：

```
values    namespace=[]
messages  namespace=[]
messages  namespace=[]
...
```

可用访问器：`stream.messages` / `.values` / `.tool_calls` / `.output` / `.lifecycle`。事件带 namespace，**多 Agent 场景下能区分是哪个子图产生的**。

⚠️ **这是实验特性**，会打 `LangChainBetaWarning`，API 可能变。做产品优先用 `stream_mode`，需要多 Agent 追溯时再上它。

## 9.7 选择建议

| 需求 | 选择 |
| --- | --- |
| Web 打字机 | `stream_mode="messages"` |
| 前端步骤条 / 工具状态 | `stream_mode="updates"` |
| 长任务进度 | `stream_mode="custom"` |
| 想看每一步完整状态（调试） | `stream_mode="values"` |
| 多 Agent 全链路追溯 | `stream_events(version="v3")`（实验） |

## 9.8 常见坑

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| 中文乱码 | `json.dumps` 默认 `ensure_ascii=True` | 加 `ensure_ascii=False` |
| 前端收到半条 JSON | 帧分隔不对 | 每帧以 `\n\n` 结尾 |
| 打印出工具内容 | 没过滤 `langgraph_node` | 只处理 `model` 节点 |
| 流式没有输出 | 思考模式只有 reasoning 增量 | 判断 `reasoning_content` |
| 多模式解包报错 | 开了多个模式但按单模式解包 | 元组解包 `for mode, payload in ...` |
