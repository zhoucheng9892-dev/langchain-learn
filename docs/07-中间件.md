# 第 7 章 中间件：v1 的灵魂

> 本章代码：`chapters/ch07_middleware/01_custom_middleware.py`、`02_builtin_middleware.py`、`03_human_in_the_loop.py`

## 7.1 本章目标

- 掌握六个钩子的执行时机与用途
- 能自己写一个中间件（动态提示词 / 审计 / 工具拦截）
- 会用内置中间件解决脱敏、限流、降级、人工审批

## 7.2 为什么有了中间件

0.x 时代，每加一个能力就给构造函数加一个参数：`handle_parsing_errors`、`max_iterations`、`callbacks`……参数越堆越多，还是覆盖不到所有需求。

v1 的答案：**把 Agent 循环切成若干可插入的时机，你只写"在某个时机做什么"。**

```
START -> before_agent -> before_model -> [模型] -> after_model
                                    -> [工具] -> ... -> after_agent -> END
              wrap_model_call 包住 [模型]
              wrap_tool_call  包住 [工具]
```

## 7.3 六个钩子

| 钩子 | 时机 | 典型用途 |
| --- | --- | --- |
| `before_agent` | 整轮开始前 | 鉴权、加载用户画像、初始化计数 |
| `before_model` | 每次模型调用前 | 注入上下文、裁剪历史、改状态 |
| `after_model` | 模型返回后 | 校验输出、统计 token、触发告警 |
| `after_agent` | 整轮结束后 | 归档、采样评测、清理资源 |
| `wrap_model_call` | 包住整次模型调用 | 重试、缓存、模型降级 |
| `wrap_tool_call` | 包住单次工具执行 | 权限拦截、参数脱敏、结果截断 |

两种写法，效果一样：

```python
# 装饰器（简单场景）
@before_model
def inject_context(state, runtime):
    return {"messages": state["messages"] + [SystemMessage("当前时间：...")]}

# 类（需要保持内部状态，比如计时器）
class AuditMiddleware(AgentMiddleware):
    def before_model(self, state, runtime):
        self._t0 = time.perf_counter()
    def after_model(self, state, runtime):
        print(f"耗时 {(time.perf_counter() - self._t0) * 1000:.0f}ms")
```

钩子返回 `dict` 就更新 state，返回 `None` 表示不改。

## 7.4 三个最有用的自定义中间件

### ① 动态提示词

```python
@dynamic_prompt
def role_prompt(request) -> SystemMessage:
    plan = request.runtime.context.plan
    return SystemMessage("你是资深理财顾问..." if plan == "pro" else "你是基础客服...")
```

比在调用处拼字符串好：人设跟着用户身份走，且只在一处维护。

### ② 工具硬拦截

```python
@wrap_tool_call
def tool_guard(request, handler):
    if request.tool_call["name"] == "transfer_money":
        return ToolMessage(content="拒绝：需人工审批", tool_call_id=request.tool_call["id"])
    return handler(request)
```

**这才叫权限控制。** 提示词里写"不要转账"是可以被绕过的；这段代码不会。

### ③ 审计

记录每次模型调用的耗时、token、工具名。第 12 章会把它做成完整的 `MetricsHandler`。

## 7.5 内置中间件清单

| 中间件 | 解决什么 | 关键参数 |
| --- | --- | --- |
| `PIIMiddleware` | 邮箱/信用卡/IP 脱敏 | `strategy="redact"`，`apply_to_input` |
| `ToolCallLimitMiddleware` | 限制工具调用次数 | `run_limit` / `thread_limit` |
| `ModelCallLimitMiddleware` | 限制模型调用次数 | 同上 |
| `ModelFallbackMiddleware` | 主模型挂了切备用 | `ModelFallbackMiddleware("备用模型")` |
| `ToolRetryMiddleware` | 工具异常自动重试 | `max_retries`、`backoff_factor` |
| `ToolErrorMiddleware` | 统一捕获工具异常 | `on_error` 回调 |
| `SummarizationMiddleware` | 历史过长自动摘要 | `trigger`、`keep` |
| `HumanInTheLoopMiddleware` | 敏感操作人工审批 | `interrupt_on={"工具名": True}` |
| `LLMToolSelectorMiddleware` | 工具太多时先筛一遍 | `max_tools` |
| `ContextEditingMiddleware` | 清理旧的工具结果 | `edits` |

实测片段：

```
PIIMiddleware  -> 模型看到的是 "请联系 [REDACTED_EMAIL] 处理退款"
ToolCallLimit  -> 第 1 次发邮件成功，第 2 次被拦，模型转述"工具调用次数已达上限"
ModelFallback  -> 主模型写了个错误名字，自动切到备用模型并正常回答
```

## 7.6 Human-in-the-loop：让人点头

```python
agent = create_agent(
    model=get_model(),
    tools=[transfer_money, get_balance],
    checkpointer=InMemorySaver(),   # 必须！中断后要能恢复
    middleware=[HumanInTheLoopMiddleware(interrupt_on={"transfer_money": True})],
)

result = agent.invoke({"messages": [...]}, config=cfg)
result["__interrupt__"]   # 有值 = 被挂起了

# 审批
agent.invoke(Command(resume={"decisions": [{"type": "approve"}]}), config=cfg)
```

四种决策：

| type | 行为 | 场景 |
| --- | --- | --- |
| `approve` | 直接执行 | 金额小、可信 |
| `reject` | 不执行，`message` 会告诉模型原因 | 超限、风控拦截 |
| `edit` | 改参数后执行 | 把 500 改成 50 |
| `respond` | 不执行，把一段话当工具结果 | 人工直接给答案 |

**必须挂 checkpointer**，否则中断后状态无处保存，`Command(resume=...)` 无从恢复。

实测（`03_human_in_the_loop.py`）：

```
[2] 待审批操作: transfer_money({'to_account': 'B456', 'amount': 500})
    可选决策  : ['approve', 'edit', 'reject', 'respond']
    此时已执行的写操作: []          <- 工具还没跑
[3] approve 后 -> ['转账 500 元 -> B456']
[5] edit 成 50 后 -> 转账 50 元 -> B456（模型申请的是 500）
```

注意第 5 步：模型被告知"人把参数改了并已授权"，所以它不会再去重试原始请求。

## 7.7 顺序很重要

`middleware=[A, B, C]` 时：

- `before_*` 按 **A → B → C**
- `after_*` 按 **C → B → A**（洋葱模型）

推荐顺序：**限流/鉴权 → 上下文管理 → 脱敏 → 审计日志**。顺序错了会出现"先花了钱再被限流""日志里记了未脱敏的手机号"这类问题。

## 7.8 常见坑

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| 中断后无法恢复 | 没挂 checkpointer | `InMemorySaver()` 起步 |
| 中间件没生效 | 钩子名拼错 / 返回类型错 | 返回 `dict` 或 `None` |
| 脱敏没起作用 | `apply_to_output` 默认 False | 显式开启 |
| 类中间件状态串了 | 用了类属性而非实例属性 | 在 `__init__` 里初始化 |
| 工具拦截后模型反复重试 | 拒绝信息太模糊 | 说明"为什么不许"和"替代方案" |
