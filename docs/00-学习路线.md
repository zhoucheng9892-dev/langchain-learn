## 0.3 环境搭建

### 安装 uv

```bash
# Windows (PowerShell)
powershell -c "irm https://astral.sh/uv/install.ps1 | iex"

# macOS / Linux
curl -LsSf https://astral.sh/uv/install.sh | sh
```

### 装依赖

```bash
cd langchain-learn
uv sync          # 按 pyproject.toml + uv.lock 精确还原
```

### 配密钥

```bash
cp .env.example .env
```

编辑 `.env`：

```ini
DEEPSEEK_API_KEY=sk-你的密钥
MODEL_NAME=deepseek-v4.1-flash
```

### 验证

```bash
uv run python chapters/ch01_quickstart/01_hello_model.py
```

看到中文回答就说明通了。

## 0.5 项目结构

```
langchain-learn/
├── docs/                       # 12 章讲义（你现在读的）
│   ├── 00-学习路线.md
│   ├── 01-快速开始.md
│   └── ...
├── chapters/                   # 33 个可运行示例，与讲义一一对应
│   ├── ch01_quickstart/
│   ├── ch02_models/
│   └── ...
├── data/                       # RAG 用的示例文档
├── src/langchain_learn/        # 公共模块（相当于你的项目脚手架）
│   ├── llm.py                  # get_model()：模型工厂 + 模型名映射
│   ├── console.py              # 终端输出美化
│   ├── embeddings.py           # 离线确定性 embedding（教学用）
│   └── rag.py                  # RAG 构建函数
├── .env                        # 密钥（不要提交）
├── pyproject.toml
└── uv.lock
```

**为什么公共代码放在 `src/langchain_learn/` 而不是 `chapters/`？**
因为项目是 `uv` 的可编辑安装包，示例脚本可以直接 `from langchain_learn import get_model`，不需要任何 `sys.path` 黑魔法。这也是真实项目的推荐组织方式。

## 0.6 三个全项目约定

### ① 所有示例都从 `get_model()` 拿模型

```python
from langchain_learn import get_model

model = get_model()                  # 关闭思考，temperature=0
model = get_model(thinking=True)     # 开启思考
model = get_model(temperature=1.3)   # 调温度
```

好处：模型名、思考开关、重试策略集中在一处；改一行就能全项目换模型。

### ② 每个示例都可独立运行

```bash
uv run python chapters/ch07_middleware/03_human_in_the_loop.py
```

不需要前置步骤（除了第 8 章的 SQLite 示例，第一次运行会自己建库）。

### ③ 输出都带分段标题

```
========================================================================
  1. 这一节在演示什么
========================================================================

[2. 小节名字]
------------------------------------------------------------------------
  ...
```

对照讲义读输出，就是"代码 → 现象 → 解释"的闭环。

## 0.7 关于 DeepSeek 的三个专属坑（提前打个预防针）

| 坑 | 现象 | 解法 |
| --- | --- | --- |
| 模型名 | 400 `The supported API model names are...` | 用 `deepseek-flash`，或用 `get_model()` |
| 思考模式 + 强制工具 | 400 `Thinking mode does not support this tool_choice` | `reasoning_effort="none"` |
| 结构化输出策略 | 400 `This response_format type is unavailable now` | `ToolStrategy(Schema)` |

这三条会在第 1、2、4 章分别复现一遍。**先说结论，后面看到报错就不会慌。**

## 0.8 学完之后

建议按这个顺序练手：

1. **改造第 1 章的 Agent**：换成你自己业务的两个工具
2. **加记忆**：用 SQLite checkpointer 做多轮
3. **加护栏**：`recursion_limit` + `ToolCallLimitMiddleware` + `ToolErrorMiddleware`
4. **接评测**：抄第 12 章的框架，写 20 条你的真实问题
5. **上线**：FastAPI + SSE（第 9 章）

做完这五步，你就不是在"学 LangChain"，而是在"用 LangChain 做产品"了。
